# 팀원용 실행 및 사용방법

이 문서는 현재 3D 웹앱의 실행, 운영 판단 API 확인, 별도 모델 추론 확인, 앞으로 연결할 실시간 관제를 순서대로 안내합니다. 실물 영상 API는 아직 구현되지 않았습니다. 요청·응답의 상세 형식은 [API 문서](API.md)를 참고하세요.

## 1. 저장소를 받고 웹앱 실행하기

처음 받는 경우:

```sh
git clone https://github.com/jikime/ppippoppippo.git
cd ppippoppippo
npm ci
npm run dev
```

이미 받은 팀원은 자신의 변경을 보존한 상태에서 다음을 실행합니다. pull 충돌이 나면 자신의 파일을 지우거나 강제 초기화하지 말고 변경을 확인합니다.

```sh
git status
git pull --ff-only
npm ci
npm run dev
```

프로젝트 README 기준 Node.js 22.12 이상이 필요합니다. 브라우저에서 `http://localhost:5173`을 엽니다. 5173 포트가 사용 중이면 strictPort 설정 때문에 실행이 실패할 수 있습니다.

API 키 없이도 3D 장면·가상 인물·이동 경로·시간표는 동작합니다. 화면 속 가상 CCTV와 LIVE 표시는 실물 영상 수신을 의미하지 않습니다.

## 2. 시뮬레이션을 이해하고 조작하기

1. **행사 일정**에서 시간표를 선택합니다. **하루 전체 재생**은 행사 1분을 시뮬레이션 1초로 압축합니다.
2. **85초 라이브 투어**를 실행하면 휴식 이동, 중앙 출입구 통제, 운영요원 배치, 동선 분산과 복구를 관찰할 수 있습니다.
3. **공간 관제**에서 출입구 상태와 인원·대기 수치를 확인하고, **인물 탐색**에서 사람의 행동과 목적지를 확인합니다.
4. 모든 문을 닫으면 사람이 경로를 기다립니다. 문을 다시 열면 이동을 재개합니다. 수치는 이 가상 상태에서 계산됩니다.
5. 키보드 `Space`는 재생·정지, `1 / 2 / 3`은 조감도·평면·실내 시점, `Esc`는 선택·정보창 해제입니다.

행사장 치수와 일부 운영 배치는 시연용 가정입니다. 이 화면의 이동·대기 수치를 실제 재난 피해 예측이나 안전 인증 결과로 발표하지 않습니다.

## 3. OpenAI 운영 판단을 연결하기

프로젝트 루트에 `.env.local`을 만들고 서버 키를 설정합니다. 아래 값은 자리표시자입니다.

```dotenv
OPENAI_API_KEY=YOUR_SERVER_API_KEY
```

키에 `VITE_` 접두사를 붙이지 않습니다. `.env.local`이나 실제 키를 Git에 커밋하지 않습니다. 설정 후 실행 중인 개발 서버를 종료하고 `npm run dev`로 다시 시작합니다.

### 연결 확인

```sh
curl http://localhost:5173/api/decisions/status
```

PowerShell에서는 `curl.exe http://localhost:5173/api/decisions/status`를 사용합니다.

`configured: true`이면 서버가 키를 읽었습니다. 실제 OpenAI 요청 성공 여부는 화면에서 **현재 상황 판단**을 한 번 실행하거나 [API 문서의 POST 예시](API.md#post-apidecisionsevaluate)를 호출해 확인합니다. 이 요청은 외부 API 사용량이 발생할 수 있습니다.

### 화면에서 사용

1. **행사 일정** 패널에서 현재 단계와 집계 인원을 확인합니다.
2. 운영 메모를 입력하고 **현재 상황 판단**을 실행합니다.
3. 조치·확신도·확률 분포·응답 시간을 확인합니다.
4. 현재 상황에 적용 가능한 제안을 적용합니다. 수동 적용에도 코드의 확신도 65% 기준이 적용됩니다.
5. 장면이나 출입구 상태가 바뀌었으면 다시 판단합니다. 오래된 응답은 적용하지 않습니다.

자동 대응을 켜면 단계 전환 시 조건에 맞는 제안을 가상 인물에 적용합니다. 패널을 닫아도 활성 상태가 이어집니다. 이는 시뮬레이션 기능이며 문자·119 연락·실제 참가자 대피 안내가 아닙니다.

## 4. 기존 모델을 맥미니에서 직접 시험하기

**이 단계는 별도 모델 작업 폴더가 이미 준비된 담당자용입니다.** 이 저장소를 clone하는 것만으로 아래 파일이 생기지 않습니다. API 서버가 아니라 기존 명령줄 추론을 실행하는 방법입니다.

필요한 구성:

```text
model-project/
  venv/                 검증된 PyTorch·Ultralytics·OpenCV 환경
  direct_infer.py
  direct_train.py        pose_features 함수에서 사용
  direct-mac/
    fire.pt              AI Hub로 학습한 화재·연기 모델
    pose.pt              기존 YOLO Pose 모델
    fall-window.pt       자세 변화 기반 낙상 분류기
```

맥미니 터미널에서 실제 모델 작업 폴더로 이동합니다. `/path/to/...`는 담당자에게 받은 경로로 바꿉니다. 임의로 모델 파일을 다운로드하거나 동명의 파일로 대체하지 않습니다.

```sh
cd /path/to/model-project

# 이미지 1장의 화재·연기 탐지
./venv/bin/python direct_infer.py --mode fire \
  --source /path/to/fire-test.jpg --weights direct-mac --device mps

# 영상의 낙상 판단
./venv/bin/python direct_infer.py --mode fall \
  --source /path/to/fall-test.mp4 --weights direct-mac --device mps
```

결과는 JSON 줄로 출력됩니다. 화재는 `class`, `confidence`, `xyxy`를 확인합니다. 낙상은 `warming_up` → `scored` 또는 `insufficient_pose` 상태를 확인하고, `score`, `threshold`, `alert`를 읽습니다. 임계값은 모델 파일의 값을 사용합니다.

기존 스크립트는 기본 최대 240개의 처리 샘플까지만 실행합니다. 무기한 운영 서비스가 아닙니다. 낙상에 사진 한 장을 넣으면 시간 정보가 없어 거절됩니다. 현재 낙상은 한 사람을 추적하는 파일럿이며 여러 사람의 낙상 감시 기능이 아닙니다.

맥미니에 직접 연결된 카메라가 있고 macOS 권한이 허용됐다면 `--source 0`으로 카메라 입력을 시험할 수 있습니다. Windows나 휴대폰의 카메라를 이렇게 지정한다고 맥미니로 전달되지는 않습니다. 브라우저 카메라는 다음 단계의 영상 전송 기능이 필요합니다.

## 5. 웹캠 실시간 관제 연결 계획

다음 단계는 **아직 구현 전**입니다. 없는 `vision_api.py`나 실행할 수 없는 `uvicorn` 명령을 현재 사용방법으로 제공하지 않습니다.

| 순서 | 개발할 내용 | 완료 확인 방법 |
| --- | --- | --- |
| 1 | 맥미니 추론 서버: 모델을 시작 시 로딩하고 API 추가 | `/health`의 모델 준비 상태와 이미지·영상 요청 확인 |
| 2 | 웹 서버 중계: 카메라 권한·인증·비공개 맥미니 연결 | 브라우저에 내부 주소·서버 인증키가 노출되지 않음 |
| 3 | 웹캠 입력: HTTPS 또는 localhost에서 카메라 허용 | 실제 카메라 화면과 프레임 촬영 확인 |
| 4 | WebSocket: 카메라 ID·시각·JPEG 전송 및 결과 수신 | 촬영한 프레임의 탐지 박스·상태가 화면에 표시 |
| 5 | 낙상 기록: 카메라별 최근 8프레임 유지 | 사람 변경·연결 끊김 때 초기화되고 판단 불가 표시 |
| 6 | 사건 처리: 지속 조건·중복 제거·대응안 | 같은 위험을 사건 하나로 관리, 실제 대응은 관리자 승인 |

첫 시험은 **카메라 1대·한 사람·4fps 입력 목표**로 시작합니다. 카메라 미리보기의 fps와 AI 처리 fps는 다릅니다. 지연이 쌓이거나 4fps를 유지하지 못하면 상태를 표시하고 낙상 기록을 안전하게 초기화하도록 설계합니다.

연결이 끊겼을 때 자동으로 정상 표시하면 안 됩니다. 서버 로그와 화면에서 연결 상태, 마지막 프레임 시각, 유효 처리 fps, 촬영부터 화면 표시까지의 지연을 확인해야 합니다. 안정적으로 동작한 뒤 카메라 수를 늘립니다.

## 6. 자주 생기는 문제

| 증상 | 확인할 것 |
| --- | --- |
| 웹이 열리지 않음 | Node 버전, `npm ci`, 터미널 오류, 5173 포트 충돌 |
| 판단 기능만 비활성 | `.env.local` 위치·서버 재시작·status 응답 |
| 키는 설정됐지만 판단 실패 | 반환 오류 메시지, 외부 API 인증·사용 권한·요청 한도 |
| 429 | 여러 팀원이 같은 서버를 호출 중인지, 2.5초 호출 간격 |
| build 결과 배포 후 API가 없음 | 정적 `dist/`에는 Node API 서버가 없음. 별도 서버 필요 |
| 낙상에서 `warming_up` | 최근 구간을 채우기 전이며 정상 판정이 아님 |
| 낙상에서 `insufficient_pose` | 가림·화각·인물 크기·자세 검출 확인 |
| 맥미니 카메라가 열리지 않음 | 실제 연결된 장비·카메라 인덱스·macOS 권한 |
| 현재 웹에서 실제 화재·낙상 알림이 안 뜸 | 아직 영상 모델을 웹에 연결하지 않았음 |

## 7. 확인된 파일럿 결과와 시연 범위

별도 모델 테스트 기록 기준입니다. 전체 다운로드 데이터를 모두 학습한 결과가 아닙니다.

| 항목 | 확인된 결과 |
| --- | --- |
| 화재·연기 | YOLO11n 50 epochs, 학습 1128장·튜닝 384장·테스트 384장. 박스 기준 정밀도 47.6%, 재현율 64.5% |
| 낙상 | 기존 YOLO Pose + 학습한 시간 구간 분류기. 테스트 977구간, 정밀도 75.3%, 재현율 70.2%, F1 72.6% |
| 낙상 정상 구간 오탐 | 17.1%. 시간당 오경보율로 해석하지 않음 |
| Mac mini | 화재 24프레임·낙상 171구간의 NHN 결과와 판정 일치 확인 |

이미지·영상 추론 실행은 확인했지만 브라우저 웹캠부터 관제 화면까지의 전체 실시간 지연은 아직 측정하지 않았습니다. 추가 화재 데이터의 재학습 결과는 위 기존 결과에 포함하지 않습니다. 총기 탐지, 실제 외부 연락, 대피 완료 확인도 현재 동작으로 발표하지 않습니다.

코드 검증 명령:

```sh
npm test
npm run build
npm run preview -- --port 4173
```

이 명령은 웹앱 코드·빌드를 확인합니다. 모델 정확도, 실제 카메라 연결, OpenAI 인증·현장 안전성을 대신 검증하지 않습니다.
